# c. 第三批 —— 邮件撰写与发送

> 目标：实现富文本撰写、附件、草稿与 SMTP 发送的完整闭环。
> 前置：第二批（邮件已可读，账户已可连接）。

## 一、目标与交付物

1. Tiptap 3 富文本编辑器 + 纯文本切换。
2. 新邮件 / 回复 / 全部回复 / 转发。
3. 附件添加（拖拽 + 文件选择）与大小校验。
4. 草稿本地自动保存与恢复。
5. SMTP 发送（mail-send）+ 发送队列 + 失败重试 + 已发送归档。

## 二、任务清单

### 1. 编辑器
- [ ] 接入 `@tiptap/react` 3.x：加粗、斜体、列表、引用、链接、图片
- [ ] 纯文本 / 富文本切换（切换时转换保留内容）
- [ ] 收件人/抄送/密送多地址输入与格式校验
- [ ] 主题行、优先级（可选）

### 2. 附件与草稿
- [ ] 附件：拖拽 + dialog 选择，显示名称/大小，发送前可移除
- [ ] 附件大小上限提示（可配置，默认 25MB）
- [ ] 草稿自动保存：本地（防抖）+ 定时（如 30s），关闭/崩溃不丢失
- [ ] 草稿恢复：重新打开编辑器时加载

### 3. 发送
- [ ] `smtp_service`：mail-send 发送，支持 SSL/STARTTLS 与 OAuth2/授权码
- [ ] `mail-builder` 构造 MIME（正文 + 附件 + 内嵌图）
- [ ] `outbox` 发送队列：立即发送，失败入队可重试，成功后移入「已发送」文件夹（IMAP APPEND）
- [ ] 发送状态反馈：发送中 / 成功 / 失败（错误信息）
- [ ] 回复/转发：引用原文、正确构造 Reply-To / In-Reply-To 头
- [ ] 签名：默认签名 + 按账户签名 + 回复前缀（`> ` 引用）

### 4. 前端 UI
- [ ] 撰写窗口/面板（新邮件、回复、转发三种入口）
- [ ] 工具栏、附件栏、发送按钮
- [ ] 发送失败 toast 与重试入口
- [ ] 「已发送」文件夹显示

## 三、验收标准

- [ ] 富文本 + 附件 + 内嵌图邮件成功送达 Gmail/QQ/163/自建 SMTP 邮箱
- [ ] 回复/转发邮件头（Reply-To / In-Reply-To / 引用）正确
- [ ] 草稿在崩溃/关窗后可完整恢复
- [ ] 发送失败（断网/密码错）进入发送队列并可重试，成功后归档「已发送」
- [ ] 收件人格式错误、附件超限有明确拦截提示

## 四、涉及模块

- `src-tauri/src/services/smtp_service.rs`、`compose_service.rs`
- `src-tauri/src/commands/compose.rs`
- `src/features/compose/`（编辑器、附件、草稿）

## 五、风险与注意

- Tiptap 3 与 2.x API 有差异，按 3.x 文档接入，避免照搬旧代码。
- 附件读取避免全量载入内存，走流式/临时文件。
- 发送成功后的 IMAP APPEND 失败不应导致邮件「看起来未发送」，需区分「已投递」与「已归档」。
